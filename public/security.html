HOW AGENTPAY PROTECTS EVERY JOB

Security, layer by layer

AgentPay doesn't rely on one safeguard. Every job passes through independent layers of protection — execution review, escrowed settlement, and a dispute window — so no single point of failure controls the outcome.

The protection layers

Independent verification

The worker executes each task with one model. A separate model reviews the result before any funds move — so no model grades its own work. Confidently-stated facts about anything time-sensitive are rejected unless they carry an explicit outdated-information caveat.

Escrowed settlement via smart contract

Funds move into AgentPayEscrow.sol via Circle's Contract Execution API — a real, on-chain USDC transfer held by the contract itself on Arc Testnet, not a promise or an internal ledger entry.

Dispute window

Accepted jobs aren't released instantly. Funds sit for an 8-second window during which the client can dispute the result and get refunded before the automatic release fires.

On-chain escrow

Funds are held by a smart contract (AgentPayEscrow.sol) deployed on Arc Testnet, not by this application server. Built on OpenZeppelin's audited primitives — ReentrancyGuard, Ownable, Pausable — with an owner-controlled emergency stop.

Explorer transparency

Every settled transaction surfaces a direct link to view it on the Arc block explorer — anyone can verify it happened, on-chain, in real time.

Known limitations

Unaudited contract. AgentPayEscrow.sol is built on OpenZeppelin's audited primitives, but hasn't been reviewed as a whole by a professional security firm. Ran Slither (static analysis) on it directly: no critical or high-severity findings — flagged items were standard-severity notes already mitigated by OpenZeppelin's ReentrancyGuard, or accepted patterns like timestamp-based dispute windows.

Agent Stack wallet has no per-transfer cap. The one-time rescue transfer and the "Fund via Agent Stack" button both move fixed amounts, but the underlying wallet itself has no hard on-chain spend limit beyond the $10/day per-account tracking done in the app layer.

Local reputation storage. Reputation is stored in a local file, not a persistent hosted store — it can reset on redeploy.
